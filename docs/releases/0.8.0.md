# v0.8.0

One PostgreSQL grammar for HTTP SQL and the PostgreSQL wire protocol.

`psql`, HTTP `/api/sql`, and the wire listener compile through the same parser and executor. `SET`, `RESET`, `SHOW`, `current_setting`, and `set_config` apply to that session. A wire connection keeps custom settings until it closes. An HTTP request keeps them for that request. `SELECT schema.function(...)` runs the catalog routine before DataFusion looks for a table function.

Server, CLI, and SDK packages are 0.8.0. Internal SDK dependency ranges are `>=0.8.0 <0.9.0`.

This is a new storage, Raft, WebSocket, and SDK cohort. It is not an in-place upgrade of a 0.6 or 0.7.1 data directory. Use an empty data directory, or export and import into a fresh database. Startup does not delete the old directory. Old MessagePack WebSocket frames are rejected. JSON remains the text form.

### SQL

- `CREATE SCHEMA` is the schema statement. `CREATE NAMESPACE` remains an alias.
- `CREATE TABLE ... WITH (TYPE = 'USER'|'SHARED'|'STREAM')` is the table statement. `CREATE USER TABLE` is rejected. `CREATE USER` creates an identity.
- A table may omit a primary key. Storage assigns a hidden `_row_id`. `SELECT *` does not return it.
- Domains, composite types, enums, sequences, and table constraints use this SQL path.
- `search_path` resolves `"$user", public`. The stored schema key `default` is not merged with a schema named `public`.
- With the wire listener enabled, `pg_catalog` views project the system catalogs.

### Serialization

Function calls and live WebSocket frames share one binary frame, `KDOM`. The server, the native Link client, browser WASM, and the Dart bridge encode and decode that frame.

- JSON stays the text form. A WebSocket connects with `serialization=json`, or with no serialization parameter. `serialization=domain` selects the binary frame. `serialization=msgpack` is rejected.
- Generated TypeScript and Dart clients call `invokeRoutine` on `/v1/functions/{schema}/{name}`. The default body is JSON. `format: 'binary'` sends the same call as a `KDOM` frame.
- Ship the server, SDKs, and generated clients together. An older SDK is rejected rather than adapted.

### PostgreSQL clients

The wire listener runs simple queries and the extended protocol: parse, describe, bind, execute, portals, and close. Prepared statements return parameter and row descriptions. Text and binary binds, `NULL` parameters, and per-connection statement limits are enforced.

- `psql`, Node.js `pg`, Python `psycopg`, Rust `tokio-postgres`, and JDBC use that listener.
- Each connection has its own transaction and `search_path`. `SAVEPOINT`, `RELEASE SAVEPOINT`, and `ROLLBACK TO SAVEPOINT` are supported. After a statement error, later commands in that transaction fail with `25P02` until `ROLLBACK`.
- `pg_catalog` and `information_schema` answer the schema, column, type, constraint, index, sequence, and routine lookups those clients send.
- The PostgreSQL extension is built and published only when that option is selected on the release workflow.

### Indexes

- Integer index keys sort numerically, so a range predicate seeks the index instead of scanning the table.
- An equality update on an indexed column reuses one plan. Inside a transaction, each staged update stays a point lookup.
- `CREATE INDEX` and a changed index definition backfill on every replica from that replica's own hot rows. A scalar index has at most four columns.
- Each primary key keeps one hot entry. The new version and the removal of the previous key land in the same write. An open transaction does not see commits that arrive after it starts.
- After a flush, `UPDATE ... WHERE id = <literal>` on a user table changes that row only.
