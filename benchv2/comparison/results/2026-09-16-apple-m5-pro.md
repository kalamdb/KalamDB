# Comparison run — 2026-09-16

Machine: **Apple M5 Pro**, 15 cores, 24 GB RAM.

Protocol unchanged: 16 in-flight HTTP requests, 100k insert wall, 10k insert
latency, 1M point reads. Timed reads consume response bytes and check HTTP
status only.

## Versions

- KalamDB **v0.7.0-dev.0** (`902bf610`), local `target/release/kalamdb-server`
- TrailBase **v0.33.14**
- PocketBase **v0.40.3**
- SurrealDB **v3.2.4** (RocksDB, REST `/key`, Bearer JWT)

KalamDB has two tracks on the same hot-only server config:

- **SQL** — parameterized `POST /v1/api/sql`
- **functions** — schema-first inline JS, `POST /v1/functions/bench/{insert_message,get_message}`
  with ABI v2 `ctx.db.execute` / `ctx.db.query` and named `input`

## Results

| Metric | KalamDB SQL | KalamDB functions | TrailBase | PocketBase | SurrealDB |
|---|---:|---:|---:|---:|---:|
| 100k inserts (wall) | 3.38 s | 11.82 s | 6.62 s | 12.30 s | 2.59 s |
| Insert p50 / p95 | 356 µs / 509 µs | 1.69 ms / 2.56 ms | 1.02 ms / 1.59 ms | 1.65 ms / 4.38 ms | 341 µs / 464 µs |
| 1M point reads (wall) | 15.05 s | 78.48 s | 49.79 s | 19.24 s | 14.31 s |
| Read p50 / p95 | 218 µs / 298 µs | 1.18 ms / 1.80 ms | 724 µs / 1.06 ms | 248 µs / 497 µs | 194 µs / 281 µs |

Raw logs: `kalamdb-20260916-094033.txt`, `kalamdb-functions-20260916-094102.txt`,
`trailbase-20260916-094234.txt`, `pocketbase-20260916-094333.txt`,
`surrealdb-20260916-094406.txt`.

Do not collapse this into a single “X is faster” headline. Writes and reads
rank differently, and KalamDB functions still pay V8 + nested SQL on every call.
