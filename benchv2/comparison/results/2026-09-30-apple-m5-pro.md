# Comparison run — 2026-09-30 (afternoon)

Machine: **Apple M5 Pro**, 15 cores, 24 GB RAM.

Protocol unchanged: 16 in-flight HTTP requests, 100k insert wall, 10k insert
latency, 1M point reads. Timed reads consume response bytes and check HTTP
status only.

KalamDB server: fresh `cargo build --release -p kalamdb-server` immediately
before the suite (`898fb92f` plus uncommitted working-tree changes). Suite
started as soon as that binary linked.

## Versions

- KalamDB **v0.7.0-beta.0** (`898fb92f`), local `target/release/kalamdb-server`
- TrailBase **v0.33.14**
- PocketBase **v0.40.3**
- SurrealDB **v3.2.4** (RocksDB, REST `/key`, Bearer JWT)

KalamDB has two tracks on the same hot-only server config:

- **SQL** — parameterized `POST /v1/api/sql`
- **functions** — schema-first inline JS, `POST /v1/functions/bench/{insert_message,get_message}`

## Results

| Metric | KalamDB SQL | KalamDB functions | TrailBase | PocketBase | SurrealDB |
|---|---:|---:|---:|---:|---:|
| 100k inserts (wall) | 3.14 s | 11.22 s | 6.83 s | 12.47 s | 2.61 s |
| Insert p50 / p95 | 335 µs / 490 µs | 1.58 ms / 2.38 ms | 1.08 ms / 1.62 ms | 1.62 ms / 4.56 ms | 359 µs / 492 µs |
| 1M point reads (wall) | 14.64 s | 78.38 s | 51.72 s | 19.95 s | 15.21 s |
| Read p50 / p95 | 212 µs / 289 µs | 1.18 ms / 1.80 ms | 750 µs / 1.07 ms | 255 µs / 523 µs | 204 µs / 303 µs |

Raw logs: `kalamdb-20260930-165143.txt`, `kalamdb-functions-20260930-165202.txt`,
`trailbase-20260930-165334.txt`, `pocketbase-20260930-165435.txt`,
`surrealdb-20260930-165509.txt`.

Do not collapse this into a single “X is faster” headline. Writes and reads
rank differently, and KalamDB functions still pay V8 + nested SQL on every call.

Versus the 2026-09-17 run on this machine, every track was faster, including
the unchanged TrailBase, PocketBase, and SurrealDB binaries. Treat that shift
as machine conditions as well as code.
