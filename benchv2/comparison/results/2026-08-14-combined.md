# KalamDB vs TrailBase/PocketBase comparison — 2026-08-14

Apple M5 Pro. Same comparison protocol for all systems: 100k inserts at concurrency 16,
10k timed inserts, then 1M point reads. Each row is one authenticated HTTP operation.
Order: KalamDB → TrailBase → PocketBase.

KalamDB used a **fresh data directory** (`setups/kalamdb/data` wiped before start), a table
without `FLUSH_POLICY`, flush scheduler disabled, and the local release binary built
today (inline PK index lookup: no `spawn_blocking` hop on `get_latest_by_index_prefix`).

| Metric | TrailBase | PocketBase | KalamDB |
|---|---:|---:|---:|
| 100k inserts | **4.957 s** | 15.681 s | 6.377 s |
| 10k timed inserts | **0.499 s** | 1.571 s | 0.708 s |
| Insert p50 | **755 µs** | 2.015 ms | 997 µs |
| Insert p95 | **1.122 ms** | 5.668 ms | 1.398 ms |
| 1M point reads | 19.193 s | 19.939 s | **17.331 s** |
| Read p50 | **247 µs** | 261 µs | 251 µs |
| Read p95 | 414 µs | 536 µs | **349 µs** |

KalamDB is fastest on total point-read time in this run (9.7% ahead of TrailBase, 13.1%
ahead of PocketBase). TrailBase remains fastest on inserts (KalamDB is 28.6% slower on
100k inserts, still well ahead of PocketBase).

KalamDB path remains `POST /v1/api/sql` with parameterized SQL. TB/PB use dedicated
Record GET/POST routes.
