# Comparison run — 2026-11-15

Machine: **Apple M5 Pro**, 15 cores, 24 GB RAM.

Protocol unchanged: 16 in-flight HTTP requests, 100k insert wall, 10k insert
latency, 1M point reads. Timed reads consume response bytes and check HTTP
status only. Two sequential passes, default order
`kalamdb kalamdb-functions trailbase pocketbase surrealdb`.

KalamDB server: `cargo build --release -p kalamdb-server` from
`bb9918e87` plus the uncommitted working tree on
`feat/0.9-unified-table-transactions`. Port **2900**. The product server
that had been listening on 2900 was stopped before the run so this used
`setups/kalamdb/server.toml` (hot-only, flush scheduler off).

Pass 2 was slower than pass 1 for every engine, and the pass-to-pass spread
is wider than on November 1. The machine had just finished a full
`cli/run-tests.sh` run, so part of the upward drift is load, not a
KalamDB-only change. Competitor binaries did not change.

KalamDB SQL point reads are faster on both passes (13.89 s, then 14.13 s)
than the November 1 mean (14.93 s) and than that run's best pass (14.70 s).
SQL inserts are slower on both passes (3.52 s, then 4.11 s) than the
November 1 band (3.15–3.18 s). The first pass is about 11% above that
band; the second pass is mixed with the machine-wide slowdown. Functions
inserts on the first pass match November 1 (4.44 s vs 4.47 s). Functions
reads stay in the same band (41.89–44.42 s vs 40.70 s).

Ranking: SurrealDB still leads inserts. TrailBase still leads reads.
KalamDB SQL is second on inserts and now second on reads (14.01 s vs
TrailBase 13.86 s), ahead of SurrealDB. On November 1, KalamDB SQL reads
were third (14.93 s), behind TrailBase and SurrealDB.
