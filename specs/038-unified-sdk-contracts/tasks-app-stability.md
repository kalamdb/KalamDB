- [ ] T112 Add deterministic fault hooks and actual-process multi-node failover/partition/rejoin/snapshot scenarios. ## Dependency and scope rules

Start T094/T109/T110 early with S/C0/D; do not wait for UI completion to discover transaction correctness defects. App slices consume the existing codec/execution owners and never create a second transaction/serializer/state engine. T107 requires actual supported command semantics, while fault/backup work runs against the real backend. Core automatic retries still wait for T034 receipts. T059/T092 optional zero-copy remain outside mandatory dependencies; T066 unsafe lifetime fixes stay P0.

Testing new data across normal schema change/crash/restore does not restore the rejected historical backward-compatibility plan. A fresh release still needs correct future behavior. Features marked conditional must either pass the fixture that uses them or remain explicitly unsupported; test stubs and unsupported-error responses do not count as a successful business feature.
